# PHASE 0 — TOTAL COMPREHENSION

## (a) What this project IS, and the dream state

**CORTEX is an autonomous operations-intelligence platform for an existing website or web app.** You integrate a browser SDK (or server webhooks), telemetry flows into an event store, a **10-phase cognitive loop** (Observe → Contextualize → Understand → Plan → Authorize → Execute → Verify → Measure → Learn → Continue) decides what to do, high-impact actions are gated behind human approval, and everything is written to an immutable audit trail. It is explicitly *not* a website builder, *not* a hosting provider, and *not* a passive analytics dashboard (README §2).

**The dream state (inferred from README, SYSTEM_MANIFEST, docs/, AUDIT_REPORT.md, the 10-day `diary/`):** CORTEX should be the *"autonomous web operations specialist"* peer of a larger agent ecosystem — independently runnable, testable and deployable, consuming AI-Universe deliberation (`FAST`/`REVIEW`/`DEBATE`), connected to 8 peer services (Inference, Memora, Stratex, IntelX, Futuris, Forge, Sentinel, FRIDAY), with "autonomy with boundaries" (policy engine + human-in-the-loop), "everything is an event", "everything is auditable", "privacy by design", and "graceful degradation" as inviolable invariants (README §4).

**Reality check:** the codebase contains a genuinely substantial architecture — 13 ORM tables, 75 API routes, 7 specialist agents, 7 tool connectors, 8 `cortex_upgrade` hardening primitives, 10 `cortex_*` packages, 205 tests — but the *operational spine* (schema bootstrap, tenant authority, webhook authenticity, WebSocket auth) is broken in ways that make the top-line README claims false today. Details in Phase 1–2.

## (d) Things that surprised me

1. **Nothing ever creates the database schema.** No `Base.metadata.create_all`, no startup hook, no `alembic upgrade` in CI/Docker/compose. A fresh boot produces an empty SQLite file, so *every* write path fails — yet dev ingestion still returns `202/200 accepted`.
2. **`npm ci` cannot build the frontend.** `package-lock.json` contains **zero** platform-native optional packages (`@next/swc-linux-x64-gnu`, `@rollup/rollup-linux-x64-gnu`, `@esbuild/linux-x64`), so `rollup`/`tsup` and `next build` fail with an explicit "npm has a bug related to optional dependencies" message. The root Dockerfile builds the dashboard with `npm ci --workspace=apps/dashboard`.
3. **The Stripe webhook handler is dead code.** `webhooks_router`'s `POST /v1/webhooks/{provider}` is registered *before* `stripe_webhook_router`, so the catch-all swallows `/v1/webhooks/stripe` — signature verification never runs.
4. **WebSocket "auth" explicitly disables signature verification** (`options={"verify_signature": False}`) in two places, plus a `token == "dev_test"` bypass. A forged JWT claiming `tenant_id=victim_corp` is accepted (proven live, see Phase 1).
5. **Real analytics is unreachable.** `/v1/analytics/{metric}` (registered earlier) shadows `/v1/analytics/funnel|cohorts|attribution`, so the FunnelEngine/CohortEngine return hardcoded demo series `[142, 189, 234]` instead.
6. **`accept()` on a test that proves nothing**: `tests/unit/test_events_and_webhooks.py:53` posts a `pk_test_live` key that no DB ever issued, asserts `200 accepted`, and the mock DB returns `None` for the key lookup — the test encodes the vulnerable anonymous-accept path.
7. **`.python-version` is UTF-16LE with a BOM** (`377 376 3 \0 . \0 1 \0 1 \0 . \0 9 \0 \r \0 \n \0`) — "3.11.9". pyenv/uv will mis-parse it.
8. **Heavy `nexus_*` → `cortex_*` rename drift remains** in `docker-compose.yml`, `infra/k8s/`, `infra/terraform/`, `infra/alembic.ini` — despite AUDIT_REPORT claiming "package alignment from `nexus_*` to `cortex_*`".
9. The repo is a **shallow clone with a single squashed commit** (`git rev-list --count HEAD` → `1`), while the docs reference an iterative history (10 diary files, two audit passes, 128 → 164 → 205 tests).
10. `AUDIT_REPORT.md` documents 23 remediated security defects and a "164 passed" run; at least six of those remediations are not effective in the shipped code (details in Phase 1 §3).

# PHASE 2 — PRIORITIZED BUG REPORT

## CRITICAL

### C1 — Unauthenticated cross-tenant event injection (multi-tenant isolation bypass)
* **Where:** `apps/api/src/cortex_api/events_router.py:110` (`auth_tenant = api_key_record.tenant_id if api_key_record else event.tenant_id`), same at `:211`.
* **Root cause:** when no `X-Cortex-Public-Key` is presented, `validate_api_key()` returns `None` and the request body's `tenant_id` is promoted to authoritative. There is no "anonymous ⇒ reject or confine to a default tenant" rule.
* **Evidence:** production-mode POST with `tenant_id: "victim_corp"` reached persistence — the 500 body shows `INSERT INTO events (..., tenant_id, ...) VALUES (..., 'victim_corp', 'site_demo', ...)`. In dev it returns `200 {"status":"accepted"}`.
* **Fix:** require a validated key (or an authenticated JWT) for ingestion; derive tenant **only** from the credential; 403 on mismatch; make "anonymous public ingestion" an explicit, disabled-by-default tenant setting.

### C2 — Unauthenticated webhook forgery + Stripe signature bypass (route shadowing)
* **Where:** `webhooks_router.py:18` (`@router.post("/{provider}")`) vs `main.py:54-55` include order (`webhooks_router` before `stripe_webhook_router`).
* **Root cause:** the catch-all `/{provider}` matches `/v1/webhooks/stripe` first, so `stripe_webhook_router._verify_stripe_signature()` (`stripe_webhook_router.py:72`) is unreachable. The catch-all trusts `X-Tenant-ID`/`X-Site-ID` headers (`webhooks_router.py:24-25`) and stores `_signature_present` without validating anything (`:50`).
* **Evidence:** `POST /v1/webhooks/stripe` with `Stripe-Signature: t=1,v1=deadbeef` → `200 {"status":"received","provider":"stripe",...}` (catch-all shape, not the Stripe handler's); `POST /v1/webhooks/anything` with `X-Tenant-ID: victim_corp` → `200` + server log `INSERT ... 'victim_corp', 'backend'`.
* **Fix:** register `stripe_webhook_router` **before** the catch-all (or drop the catch-all's `stripe` overlap), verify the provider HMAC (`cortex_upgrade/webhook.verify_hmac`) for every webhook, and derive tenant from the connector credential — never from a client header.

### C3 — WebSocket auth accepts forged tokens (any tenant's live stream)
* **Where:** `production_router.py:251` and `streaming_router.py:137` — `jwt.decode(..., options={"verify_signature": False})`; `:248`/`:133` `token != "dev_test"` bypass; unknown-tenant fallback `tenant_default`.
* **Root cause:** signature verification disabled, and the exception handler `pass`es so a bad token silently yields `tenant_default` instead of rejection.
* **Evidence:** live connect with a JWT signed by `"totally-wrong-signing-key"` claiming `tenant_id=victim_corp` → `[accepted]`, `pong` returned. `tests/unit/test_realtime_streaming.py:47` normalises the `dev_test` backdoor.
* **Fix:** verify signatures (reuse `verify_jwt_token` semantics + `is_prod` rules), reject unauthenticated upgrades with `1008`, delete the `dev_test` bypass, and gate the dev bypass behind non-production explicitly.

### C4 — 36 of 75 API routes have no authentication (including governance actions)
* **Where (top offenders, all `apps/api/src/cortex_api/understand_router.py` unless noted):**
  `/v1/approvals/pending` `:280` (tenant from a **query parameter**!), `/v1/actions/{id}/reject` `:327`, `/v1/workflows/{name}/run` `:232`, `/v1/workflows/runs/{id}` `:254`, `/v1/identity/resolve` `:33` (PII write, client-asserted tenant), `/v1/visitors/{id}/profile` `:58` (PII read), `/v1/leads/{id}/score` `:109`, `/v1/memory/{scope}/{scope_id}` `:195`, `/v1/strategies/performance` `:350`; `production_router.py`: `/metrics` `:56`, `/v1/sentinel/findings` (`GET`/`POST`), `/v1/sentinel/exposure`, `/v1/security/deployment-gate/evaluate`, `/v1/security/compliance-report`, `/v1/predictive/*`; `main.py`: `/v1/task/execute` (`:65`); `webhooks_router.py`: all.
* **Evidence:** dependency audit over `app.routes` + `original_router.routes` printed `UNAUTHENTICATED ROUTES: 36 of 75`; prod-mode probes returned `200` for `/metrics`, `/v1/predictive/traffic-forecast`, `/v1/security/compliance-report`, `/v1/approvals/pending` (500 = processing, not 401/403).
* **Fix:** apply `require_role(...)` per route (viewer for reads, operator for mutations, admin for tenant provisioning), replace client-supplied `tenant_id` with `auth["tenant_id"]`, and add a test that enumerates routes and fails if any non-allowlisted route lacks an auth dependency.

### C5 — No schema bootstrap anywhere; migrations cover only 7 of 13 tables
* **Where:** no `Base.metadata.create_all` / lifespan hook (`grep -rn "create_all" .` → only orchestrator's `session_events` variable matches); `infra/alembic/env.py:21` `target_metadata = None`; `infra/alembic.ini:53` hardcodes `postgresql+asyncpg://nexus:nexus@localhost:5432/nexus_db`.
* **Root cause:** migrations were never wired into app startup, CI, Docker, or compose; the alembic env ignores app settings and ORM metadata.
* **Evidence:** fresh boot → `sqlite3.OperationalError: no such table: events`; `alembic -c infra/alembic.ini upgrade head` → `OSError: Connect call failed ('127.0.0.1', 5432)`; migration/ORM diff: `MISSING FROM MIGRATIONS: ['approval_queue','identity_links','lead_scores','memory_entries','strategy_performance','workflow_runs']`.
* **Fix:** add a startup guard that either runs migrations or verifies schema presence; complete migrations 005+ for the 6 missing tables; drive the DSN from settings; add a "boot on empty DB" integration test.
