## Bugs I Found & Fixed
- **PostgreSQL Session FK Constraint Violation**: Events referencing sessions would fail in PostgreSQL without pre-existing session rows.
  - *Fix*: Added `_ensure_session` to persist or touch session records atomically before committing events.
- **Cross-Tenant Session Injection**: Unvalidated session IDs could be hijacked across tenant boundaries.
  - *Fix*: Enforced strict tenant ownership checks on existing sessions, rejecting foreign IDs with HTTP 403.
- **IdentityResolver Tenant Leaks**: Visitor queries looked up records by ID without tenant scoping.
  - *Fix*: Enforced `tenant_id` on all visitor and identity link queries and rejected cross-tenant visitor tampering.
- **PEL Worker Restart Reset**: In-memory retry counters reset on worker restarts, leaving poison messages stuck in PEL.
  - *Fix*: Inspected Redis `times_delivered` in `xpending_range` to acknowledge permanently failed messages.

## Key Decisions & Architecture
- Enforced strict tenant isolation invariant: cross-tenant reads return 404, cross-tenant mutations return 403.
- Standardized Postgres connection strings to support asynchronous asyncpg driver with connection pooling.
- Designed atomic session upsertion during event ingestion to maintain foreign key integrity under load.
- Aligned PEL recovery timers to 30-second intervals with 30-second minimum idle timeout.
